## 3. 项目定义（按方案 A）

**名称**：数据开发助手 —— 基于 LoRA-SFT + RAG 的 Text-to-SQL 与指标口径问答系统

**为什么选这个领域**：自己是数据开发，能造数据、能判断标注对错、面试讲得清业务逻辑；且评测可用 SQL 执行结果做硬指标，不依赖人工打分。LoRA 学「按口径输出 SQL 的格式与习惯」，公司私有的表结构 / 字段定义 / 指标口径交给 RAG 补。

**架构**：

```
原始语料/公开数据集 ──Spark/SQL 清洗去重采样──> 指令数据集(JSONL)
                                                  │
                                       LLaMA-Factory / Unsloth
                                          LoRA-SFT(7B 指令模型)
                                                  │
数据字典/表schema/口径文档 ──切分+向量化──> FAISS/Milvus ──检索──> 拼 Prompt
                                                  │
                                    FastAPI: /sql /rag /evaluate /health
                                                  │
                        自动评测(SQL执行结果比对) → 错误归因 → 回流修数据 → 再训一轮
```

**目录结构**：

```
llm-portfolio/
├── PLAN.md                    ← 本文件
├── data/            raw/  processed/  train.jsonl  eval.jsonl  (评测集独立)
├── pipeline/        clean.py  dedup.py  sample.py  quality_rules.py  build_sft.py
├── train/           lora_config.yaml  train.py  merge.py
├── eval/            run_eval.py  error_taxonomy.py  report.md
├── rag/             ingest.py  retriever.py  docs/(数据字典.md)
├── serving/         app.py  schemas.py  Dockerfile  docker-compose.yml
└── README.md        架构图 + 复现步骤 + 前后对比表
```

**方案 A 的边界**：评测只保留最小自动化版本（200 条独立评测集 + `run_eval.py` 做 SQL 执行结果比对 + 一张「基座 / v1 / v2」对比表 + 6 类错误归因占比），约 2-3 天工作量。**不做人工打分、不做 rubric、不做 LLM-as-judge、不设评测岗位**。重心放在数据流水线、训练实验、服务化。

## 7. 学习边界速查

| 档位 | 内容 |
|---|---|
| 必须懂 | token / tokenizer / 词表、上下文长度与截断、embedding 与向量检索、next-token prediction 与 loss、SFT 只对 answer 算 loss（instruction 被 mask）、epoch / lr / batch / warmup / 梯度累积 / bf16、过拟合与灾难性遗忘、LoRA 的 W 冻结 + BA 旁路 |
| 够用就懂 | Q/K/V、多头注意力直觉、位置编码（RoPE）、FFN / LayerNorm / 残差、decoder-only、KV cache、DP/TP/PP/ZeRO、vLLM / DeepSpeed 解决什么 |
| 不用碰 | 手推反向传播、手写注意力、scaling law、并行策略细节、CUDA kernel、loss spike 调优、从零复现论文 |

判断标准：**会影响怎么构造数据、怎么配训练参数、怎么解释实验结果的就要懂；只影响「怎么造模型」的先跳过。**

面试答「讲讲 Transformer」的说法：token → embedding → 多层自注意力融合上下文 → 逐 token 预测；SFT 把 instruction mask 掉只对回答算 loss；LoRA 冻结主干只训低秩旁路，所以不改注意力结构。答完把话题带到数据构建与评测。

## 8. 概念速查（避免重复解释）

- **LoRA-SFT**：用 LoRA 这种省显存方式做 SFT。是「训练 / 微调」，但不是「训练大模型（基座）」。简历写「基于 7B 开源基座完成 LoRA-SFT 监督微调」，不写「训练大模型」「自研模型」。
- **RAG**：判断标准是「有没有把检索到的内容塞进 Prompt 让模型生成答案」。只返回文档列表是检索系统，不算 RAG。企业私有知识放 RAG，微调只改行为与格式。
- **评测体系 vs 大模型测评师**：前者是写自动评测脚本 / 设计评测集 / 指标回归（本项目 `run_eval.py`），后者是人工按 rubric 打分。本项目只做前者，且只做最小版。
- **#4 岗位里的「训练」**：指 post-training（SFT / LoRA / DPO / 增量预训练），不是从零预训练。
- **项目定位**：「把现成模型调成能干特定活」，不是「造模型的人」。
