# 数据仓库数据字典与指标口径

> 本文件是 RAG 的知识源。企业私有的表结构 / 字段定义 / 指标口径放在这里，
> **不写进微调数据**——LoRA 只学「按口径输出 SQL 的行为与格式」，
> 私有知识由检索在推理时补进 Prompt。这是本项目微调与 RAG 的分工。

## 1. 分区与时间口径

所有事实表（`fact_order` / `fact_pay` / `fact_visit`）都带 `dt`（`YYYY-MM-DD` 字符串）与
`date_key`（`yyyymmdd` 整数）两套日期字段。

- **分区裁剪是硬性要求**：查询事实表必须优先用 `dt` 限定范围，禁止全表扫描。
- 推荐闭开区间写法：`dt >= '2024-03-01' AND dt < '2024-04-01'`，避免漏掉带时间戳的分区值。
- `BETWEEN '2024-03-01' AND '2024-03-31'` 只在 `dt` 为纯日期时等价。
- **MTD（月累计）**：本月 1 号至业务日期（含当日）。
- **YTD（年累计）**：本年 1 月 1 号至业务日期（含当日）。
- **自然周**用 `dim_date.week_of_year`；**工作日**用 `dim_date.is_workday = 1`；
  **月末日**用 `dim_date.is_month_end = 1`。禁止用 `strftime('%w')` 自行推断节假日。
- 环比用上一自然月同口径窗口；同比用去年同月同口径窗口。

## 2. 表结构说明

### dim_date（日历维表）

| 字段 | 类型 | 说明 |
|---|---|---|
| `date_key` | INTEGER PK | `yyyymmdd`，与事实表 `date_key` 关联 |
| `dt` | TEXT | `YYYY-MM-DD` |
| `year` / `quarter` / `month` / `day` | INTEGER | 年 / 季 / 月 / 日 |
| `week_of_year` | INTEGER | 自然周序号 |
| `is_workday` | INTEGER | 1 工作日，0 周末 |
| `is_month_end` | INTEGER | 1 表示当月最后一天 |

### dim_user（用户维表）

| 字段 | 说明 |
|---|---|
| `user_id` | 用户主键 |
| `city` | 城市（上海/北京/深圳/杭州/广州/成都） |
| `channel` | 注册渠道（app / web / mini / ads），用于渠道归因 |
| `register_dt` | 注册日期，判定新客用 |
| `vip_level` | 0-5 档；>=4 为 high，2-3 为 mid，其余 low |

### dim_product（商品维表）

`product_id` 主键；`category` 品类（数码/家居/服饰/美妆/食品）；`brand` 品牌；`price` 单价。

### fact_order（订单事实表）

| 字段 | 说明 |
|---|---|
| `order_id` | 订单主键 |
| `user_id` / `product_id` / `date_key` | 关联维表 |
| `dt` | **分区字段** |
| `amount` | 订单金额（含税，未扣退款） |
| `qty` | 件数 |
| `status` | `PAID` 有效 / `CANCELLED` 取消 / `REFUNDED` 退款 |
| `created_at` | 下单时间 |

### fact_pay（支付流水事实表）

`pay_id` 主键；`order_id` / `user_id` / `date_key` / `dt`；`pay_amount` 支付金额；
`pay_status` 取 `SUCCESS` / `FAILED`；`pay_time` 支付时间。

**注意**：同一 `order_id` 可能因重试产生多条成功流水。计算支付口径指标时必须按订单去重，
不能直接 `SUM(pay_amount)`，否则金额虚高。

### fact_visit（访问埋点事实表）

`visit_id` 主键；`user_id` / `date_key` / `dt`；`page` 页面；`duration_sec` 停留秒数。
埋点可能重复上报，计算活跃用户数一律 `COUNT(DISTINCT user_id)`。

### dim_metric（指标口径表）

`metric_code` 主键；`metric_name` 指标名；`definition` 口径定义；`sql_expr` 参考表达式；`owner` 归口团队。
口径有争议时以本表为准，不要凭字段名猜。

## 3. 指标口径定义

### GMV（成交总额）

有效订单金额之和：`SUM(amount) WHERE status = 'PAID'`。
**排除** `CANCELLED`（取消）与 `REFUNDED`（退款）订单。
常见错误：忘记过滤 `status`，把取消单算进 GMV。

### 净支付额

支付流水中支付成功的金额之和：`SUM(pay_amount) WHERE pay_status = 'SUCCESS'`。
若需按订单口径，先按 `order_id` 去重再求和。

### DAU / UV

`DAU` = 单日 `fact_visit` 中 `COUNT(DISTINCT user_id)`，必须带 `dt` 分区。
`UV`（区间）同理，但时间范围换成业务指定窗口。

### 客单价（AOV）

`GMV / 有效订单数`。分母用 `COUNT(DISTINCT order_id)`，
并用 `NULLIF(..., 0)` 防止除零。支付口径客单价则用 `SUM(pay_amount) / COUNT(DISTINCT order_id)`。

### 退款率

`status = 'REFUNDED'` 订单数 / 全部订单数，用 `SUM(CASE WHEN ... THEN 1 ELSE 0 END) * 1.0 / COUNT(*)`。

### 支付成功率

`pay_status = 'SUCCESS'` 流水数 / 全部流水数。

### 复购率

有效订单数 >= 2 的用户数 / 全部下单用户数。先按 `user_id` 聚合订单数，再在外层算比例。

### 动销品类数

指定窗口内有有效订单的去重 `dim_product.category` 数量，需关联 `dim_product`。

## 4. 常见错误与修数据指引

| 现象 | 根因 | 补哪类训练样本 |
|---|---|---|
| 结果集行数膨胀 | 缺 `DISTINCT` 或重复支付流水未去重 | 去重逻辑主题 |
| GMV 偏高 | 漏了 `status = 'PAID'` | 指标口径主题 |
| 时间范围错位 | MTD/YTD/自然周边界写错 | 时间口径主题 |
| 全表扫描 | 未用 `dt` 分区裁剪 | 分区裁剪主题 |
| 粒度错（一行变多行） | `GROUP BY` 缺列或多表 JOIN 扇出 | JOIN 聚合主题 |
